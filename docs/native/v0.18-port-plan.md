# 移植到上游 v0.18.0：现状与剩余工作

本文记录把 `upstream/photocraft` 从 v0.16.0 升到 v0.18.0 的实测结果。所有数字都来自本机实际编译，不是估算。

## 一、已完成

| 项 | 状态 | 证据 |
|---|---|---|
| 内置上游替换为 v0.18.0 | 完成 | `upstream/photocraft/Cargo.toml` `version = "0.18.0"` |
| 宿主扩展点补丁（`patches/0001-host-frame.patch`） | 完成、双架构通过 | 见下 |
| 适配层版本固定改为 0.37 / 30.0.1 | 完成 | `scripts/upstream_sync.py pins --write` |
| 上游 egui/winit 的 git 补丁段同步到适配层 | 完成 | 脚本自动生成 14 行 `[patch.crates-io]` |
| versionName/versionCode | 完成 | `0.18.0.1` / `180001` |

补丁 0001 把 v0.16 版移植里「手工把一帧拆成三份」的工作正式变成了上游扩展点：

```
cargo check -p photocraft-ui-egui --no-default-features --target aarch64-unknown-linux-ohos   # 通过
cargo check -p photocraft-ui-egui --no-default-features --target x86_64-unknown-linux-ohos    # 通过
```

规模对比很关键：

| | v0.16 的分叉 | v0.18 的补丁 |
|---|---|---|
| 改动行数 | 7620 行 / 114 个文件 | 167 增 / 82 删 / 14 个文件 |
| 升级方式 | 三方合并，72 个冲突块 | `git apply -3` 一个补丁 |

## 二、剩余工作：适配层 50 个编译错误

把 `native/rust` 指向 0.18 实测，报 50 个错误，全部落在下面五层之一。每层都可以独立成一个补丁、独立验证。

### 第 1 层：手写笔（1106 行，错误 21 个）

| 文件 | 规模 | 说明 |
|---|---|---|
| `stylus.rs` | 564 行改 | 鸿蒙 PEN 事件的压力/倾斜/接触状态机 |
| `stylus_protocol.rs` | 131 行新 | ArkTS↔Rust 的笔事件协议 |
| `chrome_ui.rs` 的笔菜单 | 411 行改 | 标题栏笔菜单、双击/长按选项 |

适配层用到的接口：`StylusFeed::{report, report_contact, report_hover, clear_hover, clear_contact, submit, source, set_display_rotation}`、`stylus::{PointerSource, StylusInput}`。

**注意**：0.18 上游自己已经有 `stylus.rs`（`app.stylus`、`pen_contacts`、`strokes` 都在用）。直接搬 v0.16 的实现等于把两套笔状态机硬拼。更省的做法是把鸿蒙的 `PenSample` 直接转成带压力/倾斜的 `egui::Event`，交给上游自己的笔逻辑，**丢掉 `StylusFeed`**——这一层就能从 1106 行降到 200 行以内，也不再需要 `chrome_ui` 的笔菜单。建议先做这个方向。

### 第 2 层：沙箱文件访问（914 行，错误 20 个）

`path_pick.rs` 339 行新、`save_dialog.rs` 192 行新、`file_ui.rs` 124 行改、`file_dialog.rs` 67 行改。

适配层缺的 `Services` 字段全在这里：`pick_open`、`pick_import`、`pick_save`、`pick_folder`、`always_pick_save`、`default_save`、`path_pickers_only`、`sandbox_dir`、`documents_dir`。

这是鸿蒙沙箱的核心约束：应用拿不到任意路径，所有读写都必须经过系统选择器。0.18 的 `file_dialog` + `FileDialogAnswer::Contents` 已经覆盖了「给内容不给路径」的一半，但仍需要补上 `pick_*` 这几个入口和路径字段只读的处理。

### 第 3 层：窗口外观（1071 行，错误 4 个）

`window_fullscreen.rs` 87 行新、`theme.rs` 289 行改（4 套 ArkUI 主题 + `chrome_css`）、`canvas.rs` 230 行改、`menus.rs` 386 行改（菜单栏折叠成汉堡）、`status_panel_controls.rs` 79 行新。

适配层缺：`Services::window_fullscreen`、`PhotocraftApp::{host_titlebar, native_doc_windows}`、`ThemeKind::chrome_css`、`canvas::DISPLAY_TEXTURE_PREFIX`。

### 第 4 层：字体与语言（286 行，错误 3 个）

`cjk_fonts.rs` 90 行改、`text/cjk.rs` 51 行改、`i18n/system.rs` 145 行改。

适配层缺：`cjk_fonts::{store_host_cjk_font, reapply_host_fonts}`、`text::cjk::set_ui_locale`、`i18n::set_host_locale`。这些是把系统字体和系统语言从 ArkTS 灌进 egui 的入口。

### 第 5 层：引擎与格式钩子（144 行，错误 2 个）

`installed_profiles.rs` 45 行改（`set_app_profile_dir`）、`prefs.rs` 75 行改、`format/atomic.rs` 24 行改（`set_host_writer`）、`Session::{print_service, print_save_service}`。

### 另有一批与版本升级直接相关的 API 漂移（与鸿蒙无关，共 6 处）

| 位置 | 0.16 → 0.18 |
|---|---|
| `egui::Event` | 新增必填字段 `source` |
| `egui_wgpu::RenderState` | 不再有 `surface_config` 字段 |
| `photocraft-format::atomic` | 写文件改为 `set_host_writer` 注入 |
| `accesskit` | `WidgetInfo.typ` → `Role`，`Role::TextEdit` 改名 |
| `PhotocraftApp::drop_target` | 改为私有，需换公开入口 |
| `i18n` | 语言从系统探测改为 `set_host_locale` 显式注入 |

这几处必须按 0.18 的新写法改，不能沿用旧调用。

## 三、建议的落地顺序

1. **第 5 层**（144 行）先做：它最小，且后面几层都要用到 `Session` 的新字段。
2. **第 4 层**（286 行）：字体是后续所有 UI 截图验证的前提。
3. **第 1 层**按上面说的「转 `egui::Event`」重写，不要搬 `StylusFeed`。
4. **第 2 层**：沙箱是鸿蒙的硬约束，做完应用才能真的打开/保存文件。
5. **第 3 层**放最后：主题和菜单折叠是观感，不影响功能跑通。

每层完成后跑：

```
cd native/rust
cargo check --target aarch64-unknown-linux-ohos
cargo check --target x86_64-unknown-linux-ohos
```

五十个错误消到零，再加上 `scripts/verify_native.py` 的 HAP 校验，才算 v0.18 移植完成。

## 四、为什么不再用「整树分叉」

v0.16 的做法是把上游拷成一份 7620 行的分叉。这次量出来：上游 v0.16→v0.18 改了 58 个文件、72 个冲突块，还把 `ui-egui` 从约 400 个扁平文件重排成 120 个文件加子目录，于是 14 个被改过的文件直接变成 `modify/delete`。单 `lib.rs` 重放 54 个补丁块有 47 个失败。

改成「pristine 上游 + 小补丁」后，同样的升级只需要重放一个 150 行的补丁。上游 0.18 甚至已经在 `logic_frame`/`ui_frame` 的注释里写明「包装型宿主自己调用尾部」，说明这条路是上游认可的。
